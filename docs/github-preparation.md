# Подготовка IZQOR к GitHub

Проект подготовлен для репозитория [dimik98330/izqor-abai](https://github.com/dimik98330/izqor-abai). Исходники размещаются в закрытом репозитории; открытая публикация и деплой выполняются отдельно.

## Что входит в выгрузку

- Исходники `src/` и `server/`, статические файлы `public/` и подготовка геоданных `scripts/`.
- Контрольная таблица населения в `tests/fixtures/`: тесты не зависят от исключённой исследовательской папки.
- `package.json` и `package-lock.json` для установки через `npm ci`.
- README, документация, атрибуция медиа и снимки текущего интерфейса.
- Пустые шаблоны `.env.example` и `.env.server.example`.
- Настройки Git, редактора, Node и workflow проверки в `.github/workflows/ci.yml`.
- Генератор оригинальной фоновой композиции `tools/generate_ambient.py` (Python + ffmpeg); он не нужен для запуска сайта.

Готовые геоданные включены. Их повторная подготовка — отдельная техническая операция: `prepare-abay-elevation.mjs` требует `sharp`, `prepare-abay-water.mjs` — `@mapbox/vector-tile` и `pbf`. Эти утилиты не запускаются при `npm ci`, проверках или сборке; дополнительные пакеты не добавлены к зависимостям приложения.

## Что исключено

`.gitignore` исключает зависимости, сборку, локальные `.env`, распространённые файлы ключей, отчёты, `.research/`, `output/`, установленные агентские навыки и машинно-зависимые браузерные скрипты из `tools/`. Локальные файлы сохранены на диске. Шаблоны переменных и генератор композиции включены отдельными исключениями.

Не загружайте рабочую папку целиком через браузер: веб-загрузка не применяет `.gitignore`. Используйте Git либо подготовленный архив `output/github-preparation/izqor-github.zip`, если он присутствует. Архив отражает состояние на момент подготовки; после изменений его нужно пересоздать.

## Проверки перед отправкой

```bash
npm ci
npm run check
npm test
npm run build
git status --short
git ls-files --others --exclude-standard
```

Проверки приложения не требуют секретов и не делают платных AI-запросов. При первом размещении workflow запустит те же команды в GitHub; результат удалённого CI станет известен только после загрузки.

## Что ещё нужно для открытой публикации

1. Подтвердить условия использования или заменить материалы с неустановленными правами из `MEDIA-CREDITS.md`: две издательские фотографии, производную иллюстрацию и встраиваемые панорамы. Сохранить атрибуцию остальных материалов.
2. Выбрать лицензию для собственного кода. Лицензия не добавлена без решения правообладателя.
3. После решения вопросов с лицензиями отдельно выбрать момент открытия репозитория. Текущая выгрузка использует закрытый доступ.
4. Для работающего публичного сайта настроить хостинг, браузерный ключ карты и отдельное размещение API гида. GitHub-репозиторий сам по себе не является деплоем.

Локальные исследовательские копии и старые снимки доступны только в рабочей папке; ссылки на них в исторических QA-заметках не являются обещанием наличия этих файлов в репозитории.

## Источники настройки CI

Официальные действия закреплены полными SHA: [actions/checkout v7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1) и [actions/setup-node v7.1.0](https://github.com/actions/setup-node/releases/tag/v7.1.0). Workflow имеет только разрешение чтения содержимого и не выполняет деплой.
